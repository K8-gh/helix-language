HELIX 0.9.2 — РУКОВОДСТВО ДЛЯ НАЧИНАЮЩИХ
=========================================

Helix — экспериментальный самостоятельный язык программирования. Исходный файл
имеет расширение .hlx. Runtime языка написан на NASM x86-64 assembly; он не
переводит программы в Python и не требует установленного Python.

В версии 0.9.2 отдельный режим `helix app` получил заголовок/размер окна и native
кнопки с действиями. Появились bridges к HTML, CSS, JavaScript, C и C++ через уже
установленные системные программы. Terminal runner сохраняет Stop/Clear, выбор файла,
Linux drag-and-drop и ввод по Enter. Это всё ещё ранняя версия языка.

1. СОЗДАНИЕ И ЗАПУСК ФАЙЛА
--------------------------

Создай текстовый файл и сохрани его как, например, hello.hlx. Самая первая строка
обязательна. Выбери один поддерживаемый режим:

    helix console
    helix console helix
    helix console windows
    helix console linux
    helix app

Как работают режимы:

- `helix console` и `helix console helix` — обычный Helix runner. В Windows
  программа выводится в собственном тёмном окне; Linux AppImage открывает
  похожее тёмное окно с выводом и вводом.
- `helix console windows` — запустить программу в отдельном настоящем окне
  системной консоли Windows. Режим доступен только в Windows-сборке.
- `helix console linux` — системный Linux terminal. В AppImage, если файл передан
  аргументом при запуске, этот режим напрямую запускает runtime в текущем terminal.
- `helix app` запускает программу в отдельном графическом окне без панели выбора
  файла. Программа может объявить заголовок, размер, до шести кнопок и числовой ввод;
  нажатие кнопки передаёт ID в `sense`. Смотри пример ниже и `examples/button_app.hlx`.
- Python backend отсутствует и намеренно не используется.

Пример собственного окна приложения:

    helix app
    app title "Helix — Счётчик"
    app size 700 500
    app button 1 "Добавить"
    app button 2 "Сбросить"
    cell count := 0
    cell event := 0
    while true
        sense event
        if event == 1
            count := count + 1
        else
            if event == 2
                count := 0
            end
        end
        pulse "Счётчик:"
        pulse count
    end

Кнопки настоящие системные controls, а не текст, нарисованный в terminal. ID каждой
кнопки должен быть уникальным числом 1..9999. До шести кнопок поддерживаются на одной
форме. В `sense` поступает ID; сравни его через `if`. Команда `app input` явно оставляет
поле числового ввода рядом с кнопками. Без кнопок обычный `sense` использует поле
ввода приложения. Canvas, произвольные layouts, произвольные типы полей и мышиные
события пока не входят в этот первый UI API.

Если выбрать системную консоль не для той ОС, Helix сообщит об ошибке платформы.
В Windows можно дважды щёлкнуть по `.hlx` (если установщик связал расширение с
Helix), затем выбрать файл и нажать «Запуск». В Linux запусти AppImage и выбери
`.hlx`; если передать путь к файлу AppImage аргументом, файл откроется сразу.

2. ПЕРВАЯ ПРОГРАММА
-------------------

    helix console
    pulse "Привет! Это моя первая программа на Helix."
    pulse 6 * 7

Ожидаемый вывод:

    Привет! Это моя первая программа на Helix.
    42

Команда `pulse` печатает строковый литерал или целочисленное выражение. Комментарий
начинается с `#` в начале отдельной строки:

    # Это заметка, её runtime не выполняет

Не добавляй комментарий после команды. Отступы делай для удобства, но блоки языка
закрываются словом `end`, а не отступом.

3. ПЕРЕМЕННЫЕ И ЧИСЛА
---------------------

Объяви числовую ячейку через `cell`:

    cell apples := 12
    cell oranges := 5
    cell total := apples + oranges
    pulse total

Чтобы обновить значение, используй `:=`:

    total := total + 1

Переменные хранят знаковые 64-битные целые числа. Можно записать `7`, `0` или
`-12`. Дробей пока нет. Имя состоит из латинских букв, цифр и `_`, начинается с
буквы или `_`, длина — до 31 символа. В одной программе не более 64 ячеек.

4. МАТЕМАТИКА И ЛОГИКА
----------------------

Операторы: `+` сложение, `-` вычитание, `*` умножение, `/` целочисленное деление,
`%` остаток. Скобки меняют порядок вычисления:

    pulse (2 + 3) * 4
    pulse 17 % 5

Сначала выполняются скобки, затем `* / %`, потом `+ -`. Деление округляется к
нулю. На ноль делить нельзя. Не рассчитывай на результат переполнения целого числа.

Булевы слова `true` и `false` — числа `1` и `0`. Для логики используй функции:

    logical_not(x)
    logical_and(a, b)
    logical_or(a, b)
    logical_xor(a, b)

Например:

    if logical_and(true, is_prime(13)) == true
        pulse "13 — простое число"
    end

5. ВВОД ИНТЕРАКТИВНЫЙ ТЕРМИНАЛ
------------------------------

`sense` читает из ввода одну строку со знаковым целым числом:

    helix console
    pulse "Сколько тебе лет?"
    sense age
    pulse "Через год будет:"
    pulse age + 1

Введи `18`, `+7` или `-4`, но не выражение `2+3`. Встроенный Helix runner
ожидает строку в нижнем поле. Нажми Enter: значение отправится без клика по
кнопке. Кнопка «Отправить» остаётся дополнительным способом. Runner позволяет
выбрать `.hlx`, запустить программу, остановить её и очистить вывод; в Linux `.hlx`
можно перетащить в окно.

Helix runner — окно запуска программ Helix, а не полноценная оболочка/эмулятор
терминала. Он не запускает произвольные команды ОС, PowerShell/CMD/WSL, PTY/ANSI
приложения или вкладки Windows Terminal.

6. УСЛОВИЯ И ЦИКЛЫ
------------------

Условие и необязательный `else`:

    if score >= 10
        pulse "Достаточно"
    else
        pulse "Продолжай"
    end

Сравнения: `==`, `!=`, `<`, `<=`, `>`, `>=`.
Самостоятельные числовые условия также допустимы: `if true`, `if count`, `while running`.
Ноль означает ложь, любое ненулевое значение — истину.

Цикл `while` повторяется, пока условие верно:

    cell i := 1
    while i <= 5
        pulse i
        i := i + 1
    end

Каждый блок `if` и `while` закрывай отдельным `end`. В цикле меняй его условие,
иначе программа может не завершиться. `for`, `break`, `continue` ещё не реализованы.

7. БИБЛИОТЕКА ЧИСЕЛ
--------------------

Вызов: `имя(аргументы)`. Аргументы разделяются запятыми; вызовы можно вкладывать:

    pulse gcd(48, 18)
    pulse max(abs(-5), sqrt(49))

В 0.9.2 доступны 53 числовые функции, 6 функций оборудования/лимитов и
`file_exists(path)` для проверки пути:

Математика: abs, sign, min, max, clamp, pow, mod, gcd, lcm, sqrt, factorial,
fibonacci, distance, average, ceil_div, midpoint, square, cube, triangular, choose.

Логика и биты: logical_not, logical_and, logical_or, logical_xor, bit_and,
bit_or, bit_xor, bit_not, shift_left, shift_right, popcount.

Свойства чисел и цифр: is_even, is_odd, is_prime, is_zero, is_positive,
is_negative, is_power_of_two, is_perfect_square, floor_log2, digit_sum,
reverse_digits, is_palindrome, digit_count, divisor_count.

Три аргумента/дополнительные операции: max3, min3, sum3, product3, clamp01.

Случайные числа и время: `random(min, max)` возвращает целое число включительно
между границами; диапазон должен содержать не более 2 147 483 648 значений. Генератор
не криптографический. `time_ms()` возвращает миллисекунды монотонных часов ОС,
`sleep_ms(ms)` приостанавливает программу на 0..86 400 000 миллисекунд.

Некоторые диапазоны: factorial(0..20), fibonacci(0..92), sqrt(n) при n >= 0,
choose(n,k) при 0 <= k <= n <= 60, is_prime(n) при 0 <= n <= 10^12,
divisor_count(n) при 0 < n <= 10^12, floor_log2(n) при n > 0, количество
сдвига 0..63. Полный справочник смотри в HELIX_AI_INSTRUCTIONS_RU.txt.

8. СВЕДЕНИЯ ОБ ОБОРУДОВАНИИ И ЛИМИТЫ
------------------------------------

Пример `examples/hardware.hlx` печатает сведения о ресурсах:

    helix console
    pulse "Доступно CPU:"
    pulse cpu_count()
    pulse "Общая память (MiB):"
    pulse memory_total_mb()
    pulse "Свободная/доступная память (MiB):"
    pulse memory_available_mb()
    pulse "Графические адаптеры, видимые ОС:"
    pulse gpu_count()

`cpu_count()` сообщает количество процессоров/ядер, доступных именно процессу.
`memory_total_mb()` и `memory_available_mb()` берут оценку у ОС. Единицы — MiB
(1 MiB = 1 048 576 байт). На Linux доступная память здесь отражает значение
freeram, поэтому она может отличаться от показателя «доступно» в системном
мониторе.

По умолчанию Helix не меняет лимиты — ресурсами управляет ОС. Необязательные
функции возвращают `1`, если ОС приняла настройку, и `0`, если нет:

    cell cpu_set := limit_cpu(2)
    cell memory_set := limit_memory_mb(1024)
    pulse cpu_set
    pulse memory_set

`limit_cpu(n)` закрепляет процесс за первыми `n` CPU, разрешёнными текущей системе.
Windows API в этой версии поддерживает до 64 CPU одной affinity-группы; Linux
работает с доступной маской до 1024 CPU. Запрашивать число выше разрешённого
можно, но ОС откажет и функция вернёт `0`.

`limit_memory_mb(n)` принимает 32..1 048 576 MiB. В Windows используется Job
Object per-process memory limit; Linux использует RLIMIT_AS — ограничение
виртуального адресного пространства процесса, а не гарантированную квоту
физических RAM. Правила ОС/контейнера могут ограничить запрос; проверяй результат.

`gpu_count()` только перечисляет графические адаптеры, видимые ОС (Windows display
devices или Linux DRM card nodes). Учитывая виртуальные адаптеры и особенности
драйвера, результат не всегда равен числу физических видеокарт. В Helix 0.9.2
нет запуска вычислений на GPU и лимита VRAM: память/вычисления видеокарты по-прежнему
контролируются ОС и драйвером.

9. ФАЙЛЫ И ТЕКСТОВЫЙ ВВОД/ВЫВОД
--------------------------------

Пример 0.9.2 находится в `examples/filesystem.hlx`. Команда `spawn` создаёт объект
в уже существующей папке назначения:

    spawn dir logs .
    spawn file session.txt logs "Старт Helix\n"

Числовые ячейки можно подставить в имя, путь и текст файла через `{имя_ячейки}`:

    cell index := 1
    cell score := 42
    spawn dir "report_{index}" .
    spawn file "data_{index}.txt" "report_{index}" "score={score}\n"
    append file "report_{index}/data_{index}.txt" "id={index}\n"

Подстановка превращает signed int64 ячейки в десятичную запись. Допускается только
имя ранее объявленной ячейки — без выражений и строковых переменных. В аргументах
файловых команд `{{` и `}}` записывают буквальные `{` и `}` (например, для JSON);
одиночная `}` остаётся обычным текстом. `pulse` по-прежнему не поддерживает
подстановки.

У `spawn file` аргументы — имя-фрагмент, папка назначения и содержимое. Имя не
может быть `.`/`..` или содержать `/` и `\\`. Файл создаётся эксклюзивно: если он
уже есть, Helix не перезапишет его. Папка назначения должна существовать; команда
создаёт только один уровень каталога.

Остальные операции:

    append file "logs/session.txt" "Вторая строка\n"
    read file "logs/session.txt"
    pulse file_exists("logs/session.txt")
    remove file "logs/session.txt"

`append file` добавляет текст в конец и создаёт файл, если его ещё нет. `read file`
выводит текстовый файл (UTF-8/текст, не произвольный бинарный поток). `remove file`
удаляет только один файл, не каталоги и не рекурсивно. `file_exists(path)` возвращает
`1`, если путь существует (файл или каталог), иначе `0`.

В аргументе содержимого `spawn file`/`append file` поддерживаются escapes `\n`
(новая строка), `\r`, `\t`, `\\`, `\"` и `\'`. Интерполяции переменных всё ещё
нет для `pulse` и произвольных строк. Файловые аргументы используют только описанный
выше `{cell}` шаблон. Пути можно заключать в кавычки, чтобы сохранить пробелы. В
путях обратные слеши остаются буквальными, например `"C:\Users\Name\Desktop"`.

Команды используют права текущего пользователя и не создают песочницу. Запускай
только доверенные `.hlx`-программы; особенно проверяй путь перед `remove file`.

10. СВЯЗКА С HTML, CSS, JAVASCRIPT, C И C++
-------------------------------------------

Helix может передать файл уже установленной системной программе. Он ничего не
скачивает и не устанавливает автоматически:

    bridge html "web/index.html"
    bridge css "web/style.css"
    bridge js "scripts/task.js"
    bridge c "native/hello.c"
    bridge cpp "native/hello.cpp"

- `bridge html` открывает HTML через системный обработчик (обычно браузер). HTML
  подключает CSS и JavaScript стандартными элементами `<link>` и `<script>`.
- `bridge css` открывает CSS системным приложением для этого типа файла. CSS —
  таблица стилей, а не самостоятельная программа.
- `bridge js` запускает Node.js (`node` в Linux, `node.exe` в Windows).
- `bridge c` использует имеющийся в `PATH` компилятор `cc`/`gcc`.
- `bridge cpp` использует имеющийся в `PATH` компилятор `c++`/`g++`.

C/C++ компилируются во временный файл, запускаются, затем временный файл удаляется;
исходник остаётся на месте. Для открытия HTML/CSS нужна графическая сессия и системная
ассоциация. Если tool отсутствует, появится сообщение; Helix не загружает dependencies
сам. Внешний код работает с правами пользователя, не в sandbox.

11. ЧЕГО ЕЩЁ НЕТ
----------------

Нет пользовательских функций, массивов/списков, строковых переменных, склеивания
строк, дробей, `for`, `break`, `continue`, классов, модулей, сетевого API,
исключений, указателей или GPU kernels. Текст нельзя хранить в переменной; `pulse`
принимает строку только непосредственно в кавычках. `helix app` ограничен шестью
кнопками, числовыми ID событий и вводом `sense`; это пока не общий GUI framework.

Чтобы другие модели генерировали корректный код, дай им файл
`HELIX_AI_INSTRUCTIONS_RU.txt`: это точная спецификация поддерживаемого языка.

Удачи! Начни с hello.hlx, затем запусти калькулятор и gemini_level3.hlx.

12. LINUX APPIMAGE
------------------

В комплекте есть `Helix-0.9.2-x86_64.AppImage`: один переносимый файл для обычных
64-битных Intel/AMD Linux-систем. Он содержит тёмное окно Helix, Linux runtime и
нужные GTK-библиотеки; отдельная установка Helix или Python не требуется.

Скачай файл, открой свойства и разреши выполнение либо выполни в терминале:

    chmod +x Helix-0.9.2-x86_64.AppImage
    ./Helix-0.9.2-x86_64.AppImage

По желанию добавь приложение в меню только для своего пользователя (без `sudo`):

    ./Helix-0.9.2-x86_64.AppImage --install

Установщик копирует AppImage в `~/Applications` и создаёт ярлык и иконку в
`~/.local/share`. Для удаления запусти установленную копию:

    ~/Applications/Helix-0.9.2-x86_64.AppImage --uninstall

Установка не меняет системные пакеты и не настраивает автоматическую ассоциацию
файлов `.hlx`.

Затем нажми «Обзор...», выбери `.hlx`, нажми «Запуск». Ввод в нижнее поле можно
отправить клавишей Enter. Чтобы сразу открыть программу, передай её путь:

    ./Helix-0.9.2-x86_64.AppImage /путь/к/программе.hlx

Если файл начинается с `helix console linux` и передан при запуске AppImage, он
запустится прямо в текущем системном терминале. Для такого запуска используй
терминал, а не ярлык файлового менеджера.

Сборка сделана на Ubuntu 24.04 x86_64; здесь проверены сам AppImage, Linux runtime,
GUI-запуск под виртуальным X-сервером и языковые smoke-тесты. Фактического доступа к
компьютерам друзей с CachyOS/Debian не было, поэтому эти дистрибутивы являются
целевыми, но не физически протестированными системами. AppImage ориентирован на
современные glibc-дистрибутивы. Если появится ошибка FUSE, попробуй запуск:

    APPIMAGE_EXTRACT_AND_RUN=1 ./Helix-0.9.2-x86_64.AppImage

Если AppImage откроется, но графическая сессия недоступна, запускай CLI runtime из
архива: `./dist/helix-linux-x86_64 программа.hlx`.


10. РАБОТА С ДРУГИМИ ФАЙЛАМИ HELIX
-----------------------------------

Разделяй программу на файлы и запускай модуль как отдельный Helix script:

    bridge helix "index.hlx"

В графическом runner относительные пути ищутся от каталога `main.hlx`. Дочерний файл должен начинаться с допустимого заголовка Helix и выполняется тем же runtime. Это не общий namespace: переменные `cell` между процессами не передаются автоматически. Существующие bridges `html`, `css`, `js`, `c`, `cpp` сохранены; нужные системные инструменты не скачиваются.

11. СИСТЕМНЫЕ ДИАЛОГОВЫЕ ОКНА
------------------------------

Для простого сообщения:

    dialog "О программе" "Привет из Helix"

Для запроса Yes/No объяви переменную результата:

    cell answer := 0
    dialog answer "Подтверждение" "Продолжить?"
    if answer == 1
        pulse "Выбрано Да"
    else
        pulse "Выбрано Нет"
    end

После Yes ячейка содержит 1, после No — 0. `{answer}` можно использовать в title/message для числовой подстановки. Окно системное и блокирующее. Функция предназначена для `helix app`: Windows использует MessageBoxW, Linux GTK runner — GtkMessageDialog. В console-only режиме сообщение выводится текстом, ожидания ответа нет, результат — 0.

Для GUI-приложения app-оболочка не показывает terminal output view и не является консолью со скрытой строкой ввода. Используй `app button`, `app input` и `sense` для интерактивного UI.
