HELIX 0.9.2 — СПЕЦИФИКАЦИЯ ДЛЯ ИИ, ПИШУЩИХ КОД
=================================================

НАЗНАЧЕНИЕ
----------
Это нормативный справочник синтаксиса экспериментального языка Helix 0.9.2.
Генерируй только реально поддерживаемый код `.hlx`. Не подменяй Helix Python,
C, C++, C#, Java или другим языком. Helix runtime написан на NASM x86-64; Python
backend не существует и не должен предлагаться как доступный режим.

Helix 0.9.2 остаётся ранним языком, а не полноценной заменой зрелых экосистем.
Доступны 64-битные целые, ячейки, вывод/ввод, if/while, файловые команды, 53
числовых built-ins, 4 аппаратных query-функции и 2 resource setter-функции.

1. ЗАГОЛОВОК ФАЙЛА И РЕЖИМ КОНСОЛИ
----------------------------------

Файл должен быть UTF-8 без BOM, с расширением `.hlx`. Первая строка — ровно одна
из следующих директив:

    helix console
    helix console helix
    helix console windows
    helix console linux
    helix app

`helix console` и `helix console helix` выбирают стандартный Helix runner.
`helix console windows` просит настоящую системную консоль Windows; этот backend
доступен только Windows-сборке. `helix console linux` использует обычную системную
консоль Linux и доступен только Linux-сборке. Несовпадение ОС вызывает ошибку.
`helix app` в GUI runner Windows/Linux запускает `.hlx` в отдельном app-окне без
панели выбора файла. До начала обычного кода могут находиться host-директивы:

    app title "Заголовок"
    app size 700 500
    app button 1 "Сохранить"
    app input

`app title` принимает одну простую строку в двойных кавычках. `app size width height`
принимается в диапазонах width 480..1600 и height 320..1200 пикселей. Можно задать до
6 кнопок с уникальными целочисленными ID 1..9999 и непустыми подписями. В нажатии
кнопки runner передаёт её ID следующему `sense`; обрабатывай ID обычным `if/else`.
`app input` явно оставляет числовое текстовое поле одновременно с кнопками. Без
кнопок `sense` получает данные из app-ввода по Enter. Декларации разбирает GUI host;
standalone runtime игнорирует их как host metadata.

Это минимальный native widget API (заголовок, размер, кнопки и числовой ввод), а не
общий GUI framework: нет canvas, layouts, произвольных типов controls или мышиных
событий. Не генерируй другие `app`-директивы.

Python mode удалён и не поддерживается. Не генерируй `helix console python`.
В Windows GUI-runner имеет отдельное окно; Linux AppImage предоставляет аналогичный
по назначению тёмный GTK-runner. Linux CLI работает в терминале, из которого
запущен бинарник. Если AppImage получает `.hlx` с заголовком
`helix console linux` аргументом командной строки, он передаёт запуск системному
Linux terminal. При выборе такого файла из GUI без TTY пользователь увидит подсказку.

Минимальный интерактивный app-файл:

    helix app
    pulse "Квадрат числа"
    pulse "Введите целое число и нажмите Enter:"
    sense number
    pulse "Результат:"
    pulse number * number

Валидный app пример:

    helix app
    app title "Helix Counter"
    app size 700 500
    app button 1 "Add"
    app button 2 "Reset"
    cell count := 0
    cell event := 0
    while true
        sense event
        if event == 1
            count := count + 1
        else
            if event == 2
                count := 0
            end
        end
        pulse count
    end

В app режиме кнопки/поля создаются runner-ом, а не языковым runtime; весь бизнес-код,
ветвление и состояние остаются командами Helix. Валидный пример также находится в
`examples/button_app.hlx`.

После заголовка записывай одну команду на строку. Блоки закрывай `end`; отступы
служат для чтения, а не задают структуру. Комментарии — только отдельной строкой,
начинающейся с `#`. Не добавляй inline-комментарии после команд. Длина строки
исходника — максимум 4095 байт с учётом завершающего нуля буфера.

Имена переменных: ASCII-буквы, цифры и `_`; первый символ — буква или `_`;
максимум 31 символ. Максимум 64 ячеек. Имена чувствительны к регистру.

2. ТИПЫ, ЛИТЕРАЛЫ И ОПЕРАТОРЫ
-----------------------------

Единственный пользовательский тип — signed int64:
-9223372036854775808 .. 9223372036854775807.

`true` равно 1, `false` равно 0. Дробей, null, строковых переменных и коллекций
нет. Отрицательные литералы поддерживаются, например `-17`.

Арифметические выражения:

    (expression)      группировка
    * / %             умножение, signed целочисленное деление, остаток
    + -               сложение, вычитание

`* / %` имеют больший приоритет, чем `+ -`; операции левоассоциативны. Деление
округляется к нулю. Деление/остаток по нулю и signed overflow INT64_MIN / -1
вызывают контролируемую ошибку. Не полагайся на переполнение сложения, вычитания,
умножения и сдвига: избегай его.

Сравнения `==`, `!=`, `<`, `<=`, `>`, `>=` поддерживаются в условиях `if` и
`while`. Также допустимо standalone числовое/boolean условие, например `if true`,
`if count`, `while running`: ноль — false, ненулевое значение — true. Не предполагай,
что сравнения доступны как самостоятельные значения выражения. Не используй операторы
`and`, `or`, `not`, `+=`, `++`, `**`, `//`,
`&`, `|`, `^` или `!`; для логики/битов применяй встроенные функции.

3. ЯЧЕЙКИ, ВЫВОД И ВВОД
----------------------

Первое объявление:

    cell score := 10

Обновление:

    score := score + 1

Вывод числа:

    pulse score
    pulse 6 * 7

Вывод строки:

    pulse "Привет, Helix!"

Строка в `pulse` принимается только как простой литерал. Нельзя хранить строку в
ячейке, объединять строки или передавать строку числовой функции. `pulse` не
поддерживает интерполяцию. Только файловые аргументы имеют ограниченный `{cell}`
шаблон (см. раздел 5); не используй его в `pulse` или обычных строках.

Ввод одной signed decimal integer строки:

    pulse "Введите целое число:"
    sense count

`2+3`, дробь, пустая строка и буквы — некорректный ввод. В GUI-runner пользователь
вводит значение в поле и нажимает Enter; кнопка отправки остаётся необязательной.

4. УСЛОВИЯ И ЦИКЛЫ
------------------

    if score >= 10
        pulse "Достаточно"
    else
        pulse "Продолжай"
    end

`else` необязателен. `if` и `while` можно вкладывать; максимум 64 открытых блоков.
Сравнение не обязательно: любое целочисленное выражение является условием, где 0 —
false, ненулевое — true. Например, `if true`, `if count`, `while running` допустимы.

    cell index := 1
    while index <= 5
        pulse index
        index := index + 1
    end

У каждого открытого `if`/`while` должен быть `end`. Каждая ветвь/итерация — команда
на строке. `for`, `break` и `continue` не реализованы. Проверяй, что while изменяет
управляющую переменную, чтобы не создать бесконечный цикл.

5. ФАЙЛОВЫЕ КОМАНДЫ, СЛУЧАЙНОСТЬ И ВРЕМЯ
-----------------------------------------

Файловые команды запускаются с обычными правами текущего пользователя, sandbox нет.
Используй только точные пути. Не генерируй `remove file`, если пользователь явно не
попросил удалить конкретный файл.

    spawn dir <name> <parent-directory>
    spawn file <name> <parent-directory> "<content>"
    append file "<path>" "<content>"
    read file "<path>"
    remove file "<path>"

- `spawn dir` создаёт одну новую директорию внутри уже существующей папки.
- `spawn file` создаёт новый файл эксклюзивно: существующий файл никогда не
  перезаписывается. `<name>` — один компонент; запрещены `.`, `..`, `/`, `\\`.
- `append file` добавляет данные в конец, создавая файл, если его ещё нет.
- `read file` печатает текстовый UTF-8 файл построчно; это не binary I/O, содержимое
  нельзя поместить в переменную.
- `remove file` удаляет один файл и не удаляет каталоги/деревья рекурсивно.
- `file_exists("<path>")` — числовое выражение, возвращает `1` для файла ИЛИ
  каталога, `0` для отсутствующего пути.

Во всех аргументах файловых команд и `file_exists` работает простая подстановка
`{cell_name}`: ранее объявленная числовая ячейка заменяется десятичной signed int64
записью. Это позволяет строить динамические имена и записывать значения ячеек:

    cell record_id := 1
    cell score := -42
    spawn dir "records_{record_id}" .
    spawn file "data_{record_id}.txt" "records_{record_id}" "score={score}\n"
    append file "records_{record_id}/data_{record_id}.txt" "id={record_id}\n"
    pulse file_exists("records_{record_id}/data_{record_id}.txt")

Подстановка принимает только один идентификатор внутри скобок; выражения, вложенные
placeholders и строковые переменные не поддерживаются. Ячейка должна быть объявлена
до команды; неизвестное имя вызывает `unknown variable`. После подстановки имя всё
ещё проверяется как один безопасный компонент пути. `{{` и `}}` дают буквальные
фигурные скобки в файловом аргументе (полезно для JSON); одиночная `}` копируется.

Путь с пробелами заключай в двойные кавычки. В Windows обычный одиночный обратный
слеш `\` пути сохраняется буквально; удваивать его не нужно:

    spawn dir test "C:\Users\Kirill\Desktop"
    spawn file hello.txt "C:\Users\Kirill\Desktop\test" "Привет\n"
    append file "C:\Users\Kirill\Desktop\test\hello.txt" "Ещё строка\n"
    read file "C:\Users\Kirill\Desktop\test\hello.txt"

Только в аргументе содержимого `spawn file` и `append file` декодируются `\n` (LF),
`\r`, `\t`, `\\`, `\"`, `\'`. Escapes обрабатываются до `{cell}` подстановки.
Не используй произвольные escape-последовательности или строковые переменные.

    random(min, max)   целое из включительного диапазона [min, max]
    time_ms()          миллисекунды монотонных часов ОС, не календарная дата
    sleep_ms(ms)       задержка в диапазоне 0..86 400 000 миллисекунд

У `random` должно быть `min <= max`, ширина включительного диапазона <= 2^31.
Генератор не криптографический: никогда не используй его для паролей, ключей или
токенов.

6. СТАНДАРТНАЯ ЧИСЛОВАЯ БИБЛИОТЕКА (53)
-----------------------------------------

Синтаксис вызова: `function(arg1, arg2, ...)`. Аргументы — expressions, разделены
запятыми. Вложенные builtin вызовы поддерживаются; maximum arity — 3.

МАТЕМАТИКА
  abs(x)                       |x|; INT64_MIN не представим как положительный abs
  sign(x)                      -1, 0 или 1
  min(a, b)                    меньший аргумент
  max(a, b)                    больший аргумент
  clamp(x, low, high)          clamp; требует low <= high
  pow(base, exponent)          целая степень; 0 <= exponent <= 63
  mod(a, b)                    signed remainder; b != 0
  gcd(a, b)                    НОД; абсолютные значения должны помещаться в int64
  lcm(a, b)                    НОК; следи за переполнением результата
  sqrt(n)                      целый корень вниз; n >= 0
  factorial(n)                 n!; 0 <= n <= 20
  fibonacci(n)                 Fibonacci; 0 <= n <= 92
  distance(a, b)               модуль разности; результат должен помещаться
  average(a, b)                целочисленное среднее, усечение к нулю
  ceil_div(a, b)               деление вверх; b != 0; не вызывай INT64_MIN/-1
  midpoint(a, b)               безопасная целочисленная середина
  square(x)                    x*x; результат должен помещаться
  cube(x)                      x*x*x; результат должен помещаться
  triangular(n)                n*(n+1)/2; n >= 0, результат помещается
  choose(n, k)                 сочетания; 0 <= k <= n <= 60

ЛОГИКА И БИТЫ
  logical_not(x)               1, если x == 0, иначе 0
  logical_and(a, b)            1, если оба ненулевые, иначе 0
  logical_or(a, b)             1, если хотя бы один ненулевой
  logical_xor(a, b)            1, если ровно один ненулевой
  bit_and(a, b)                64-битовое побитовое AND
  bit_or(a, b)                 64-битовое побитовое OR
  bit_xor(a, b)                64-битовое побитовое XOR
  bit_not(x)                   64-битовое NOT
  shift_left(x, count)         сдвиг; 0 <= count <= 63
  shift_right(x, count)        logical unsigned shift; 0 <= count <= 63
  popcount(x)                  количество единичных битов 64-битного слова

СВОЙСТВА ЧИСЕЛ И ЦИФР
  is_even(n)                   1, если чётное
  is_odd(n)                    1, если нечётное
  is_prime(n)                  проверка простоты; 0 <= n <= 10^12
  is_zero(x)                   1, если x == 0
  is_positive(x)               1, если x > 0
  is_negative(x)               1, если x < 0
  is_power_of_two(n)           1 для положительной степени 2
  is_perfect_square(n)         1 для квадрата; отрицательное — false
  floor_log2(n)                floor(log2(n)); n > 0
  digit_sum(n)                 сумма десятичных цифр; n >= 0
  reverse_digits(n)            перевёрнутые цифры; n >= 0
  is_palindrome(n)             число-палиндром; n >= 0
  digit_count(n)               число десятичных цифр; n >= 0, count(0)=1
  divisor_count(n)             число положительных делителей; 0 < n <= 10^12

ДОПОЛНИТЕЛЬНЫЕ
  max3(a, b, c)                 максимум
  min3(a, b, c)                 минимум
  sum3(a, b, c)                 сумма
  product3(a, b, c)             произведение; результат должен помещаться
  clamp01(x)                    ограничение x диапазоном 0..1

Все арифметические результаты должны помещаться в int64. Если указан диапазон,
не вызывай функцию вне диапазона: runtime завершится ошибкой. Внутренние проверки
диапазона могут быть строже приведённого математического описания; никогда не
генерируй граничные/переполняющиеся случаи без необходимости.

7. API СВЕДЕНИЙ ОБ ОБОРУДОВАНИИ И РЕСУРСАХ
-------------------------------------------

Все шесть функций используют штатные платформенные API, никаких сторонних
Python/SDK-библиотек в `.hlx`-программе не требуется.

  cpu_count()                 число CPU, доступных текущему процессу
  memory_total_mb()           общий объём физической памяти, MiB
  memory_available_mb()       доступная/свободная физическая память, MiB
  gpu_count()                 число графических/display/DRM адаптеров от ОС
  limit_cpu(n)                установить affinity процесса, вернуть 1/0
  limit_memory_mb(n)          ограничить память процесса, вернуть 1/0

Ограничения `limit_cpu`:
- n > 0;
- Windows принимает не более 64 CPU в одной processor affinity group;
- Linux принимает n <= 1024, но выбирает CPU из текущей разрешённой маски;
- если ОС не может применить запрошенное число, функция возвращает 0;
- успешно применённый affinity остаётся у данного процесса до его завершения.

Ограничения `limit_memory_mb`:
- 32 <= n <= 1 048 576 MiB;
- Windows использует Job Object PROCESS_MEMORY_LIMIT и может отказать, если процесс
  уже состоит в ограничивающей job/среда запрещает присоединение;
- Linux устанавливает soft/hard RLIMIT_AS для virtual address space; это не
  эквивалент физической RAM квоты и не резервирует указанное число RAM;
- функция возвращает 1 только если ОС приняла настройку, иначе 0.

Если limit function не вызвана, runtime не назначает свой CPU/RAM cap: обычное
управление ресурсами остаётся за ОС, контейнером и системными ограничениями.

GPU-ограничение принципиально: `gpu_count()` только перечисляет адаптеры, видимые
ОС (Windows EnumDisplayDevices; Linux `/sys/class/drm/cardN/device`). Это может
включать виртуальные адаптеры/дисплеи; число не гарантирует число GPU, доступных для
compute. В версии 0.9.2 нет выбора GPU, чтения VRAM, выделения VRAM или запуска GPU
kernel. Не утверждай, что Helix выполняет GPU-вычисления или ограничивает их.

8. BRIDGES К СИСТЕМНЫМ ЯЗЫКОВЫМ ИНСТРУМЕНТАМ
-------------------------------------------

Helix 0.9.2 принимает отдельную statement-команду с точным синтаксисом:

    bridge html "web/index.html"
    bridge css "web/site.css"
    bridge js "scripts/task.js"
    bridge c "native/main.c"
    bridge cpp "native/main.cpp"

- `html`: открыть существующий HTML системной association (обычно браузером).
- `css`: открыть существующий CSS системным default handler; CSS сам по себе не
  исполняется. HTML подключает CSS/JS через обычные `<link>`/`<script>`.
- `js`: выполнить файл через установленный `node` (Linux) или `node.exe` (Windows).
- `c`: на Linux — уже доступный в PATH `cc`; Windows — `gcc.exe`.
- `cpp`: на Linux — `c++`; Windows — `g++.exe`.

C/C++ bridge синхронно вызывает внешний compiler, записывает результат во временный
executable, запускает его, затем удаляет временный executable; пользовательский
исходник не меняет. Bridge не скачивает и не включает браузер/Node/compiler в Helix.
Если программа отсутствует, runtime показывает ошибку; при наличии инструмента его
version/совместимость определяет системная установка пользователя. Внешний код
работает с обычными правами текущего пользователя, без sandbox.

Путь передавай quoted, если он содержит пробелы. `{cell}` подстановка числового
значения поддерживается в bridge path так же, как в файловом аргументе; `{{`/`}}`
дают буквальные фигурные скобки. Не придумывай другие имена bridge или дополнительные
аргументы.

9. ЧЕГО НЕ ГЕНЕРИРОВАТЬ
-----------------------

Следующие конструкции отсутствуют:
- пользовательские `fn`, `return`, рекурсия, локальные области видимости;
- массивы, списки, словари, наборы, строки в переменных, конкатенация;
- дробные числа, decimal, null/None;
- `for`, `break`, `continue`, классы/структуры/enum;
- import/modules/packages, сетевой API, исключения;
- указатели, ручное управление памятью, встроенный компилятор (C/C++ доступны только
  через описанный внешний bridge при наличии пользовательского compiler);
- GPU compute, VRAM control, shell/PTy/VT terminal APIs.

`helix console python`, Python syntax (`print`, `def`, `let`, braces, semicolon,
list/dict, `==` assignment, `+=`, `++`) не поддерживаются. Не объявляй свойства
языка по аналогии с Python/C/C++/C#/Java, если их нет в этом документе.

10. ПРОВЕРЕННЫЙ ШАБЛОН КОДА
--------------------------

    helix console
    pulse "Введите два неотрицательных числа:"
    sense a
    sense b
    cell common := gcd(a, b)
    pulse "НОД:"
    pulse common

ДОПОЛНЕНИЕ v0.9.2: MODULE BRIDGE И DIALOG API
=============================================

`bridge helix "index.hlx"` запускает отдельный Helix runtime для указанного файла. Относительный путь считается от рабочего каталога процесса (GUI host задаёт каталог main script). Это не import общего namespace: ячейки дочернего файла остаются в отдельном процессе.

`dialog "Заголовок" "Текст"` показывает системный OK dialog. Для Yes/No создай cell до вызова: `cell result := 0`, затем `dialog result "Заголовок" "Вопрос"`. Значение result становится 1 при Yes или 0 при No. `{cell}` подставляется числом в обе строки.

В Windows app runtime использует MessageBoxW, в Linux app — GtkMessageDialog. Это блокирующая GUI-команда; используйте её в `helix app`, а не в console-only скрипте. Без GUI host runtime сообщает о недоступности и устанавливает result в 0.

App mode теперь скрывает terminal output view и показывает отдельную поверхность приложения с объявленными кнопками/полем ввода. Не рассчитывай на консольный вывод `pulse` внутри app shell.
