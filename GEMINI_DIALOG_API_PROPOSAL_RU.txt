ПРЕДЛОЖЕНИЕ ПО РАЗРАБОТКЕ: НАТИВНЫЕ ДИАЛОГОВЫЕ ОКНА (DIALOG API)
ЯЗЫК: Helix (версия 0.9.2 / proposal)
===================================================================

1. ОПИСАНИЕ ИСХОДНОГО ИНТЕРФЕЙСА (ПО СКРИНШОТУ)
----------------------------------------------
На предоставленном образце изображено классическое всплывающее системное
диалоговое окно (MessageBox):
- Заголовок окна: "Текст заголовка"
- Тело сообщения: "Текст сообщения"
- Иконка: Красный круг с белым крестом (стандартный значок ошибки / Error / Critical)
- Кнопки управления: Две кнопки — "Да" и "Нет".

2. ПРЕДЛАГАЕМЫЙ СИНТАКСИС ДЛЯ HELIX
-----------------------------------
Для сохранения стиля языка предлагается добавить команду `dialog`.
Команда имеет две формы: простая (информационная) и интерактивная (с выбором).

Форма 1: Информационное окно (OK)
    dialog "<Заголовок>" "<Текст сообщения>"

Форма 2: Диалог подтверждения (Да / Нет) с сохранением ответа в ячейку.
Возвращает 1 (Да / Yes) или 0 (Нет / No).
    cell result := 0
    dialog result "<Заголовок>" "<Текст сообщения>"

Пример использования в Helix .hlx:

    helix app
    app title "Утилита с диалогами"

    cell user_choice := 0
    dialog user_choice "Текст заголовка" "Текст сообщения"

    if user_choice == 1
        pulse "Пользователь выставил ДА"
    else
        pulse "Пользователь выставил НЕТ"
    end

3. ТЕХНИЧЕСКАЯ РЕАЛИЗАЦИЯ В RUNTIME
----------------------------------

А) Windows (NASM x86-64 / user32.dll)
Для реализации используется вызов функции MessageBoxW или MessageBoxA из user32.dll.

Параметры вызова MessageBoxW:
- hWnd = NULL (0)
- lpText = Указатель на UTF-16/ASCII строку сообщения
- lpCaption = Указатель на UTF-16/ASCII строку заголовка
- uType = MB_YESNO (0x00000004) | MB_ICONERROR (0x00000010)

Код возврата:
- IDYES (6) -> записываем 1 в ячейку Helix
- IDNO (7) -> записываем 0 в ячейку Helix

Пример сборки аргументов на NASM x64:
    sub rsp, 40                 ; Выравнивание стека и shadow space
    mov rcx, 0                  ; hWnd
    lea rdx, [rel msg_text]     ; lpText
    lea r8,  [rel msg_title]    ; lpCaption
    mov r9d, 0x14               ; MB_YESNO | MB_ICONERROR
    call [rel __imp_MessageBoxA]
    add rsp, 40

    cmp eax, 6                  ; IDYES
    je .pressed_yes
    mov qword [cell_result], 0
    jmp .done
.pressed_yes:
    mov qword [cell_result], 1
.done:

Б) Linux (GTK3 / X11 / CLI)
Для Linux runner (GTK AppImage / CLI) диалог реализуется через GtkMessageDialog
или вызов системной утилиты zenity/kdialog при отсутствии GTK-контекста.

Использование GtkMessageDialog:
- flags = GTK_DIALOG_MODAL
- type = GTK_MESSAGE_ERROR
- buttons = GTK_BUTTONS_YES_NO

Ответ GTK_RESPONSE_YES трансформируется в 1, остальные ответы — в 0.

4. ОГРАНИЧЕНИЯ И ПРАВИЛА
------------------------
- Команда `dialog` является блокирующей (выполнение кода останавливается до закрытия окна).
- Поддерживается подстановка `{cell}` в тексте сообщения и заголовка, аналогично файловым командам.
